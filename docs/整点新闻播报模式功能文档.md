## 一、功能概述

每日 9:00~22:00 共 14 个整点档，设备自动接管屏幕播报闲沐云平台 `news_hourly` 当档新闻（WAV 音频经 MAX98357A 功放输出，播报稿文字同步上屏）。

1. **全局服务**：整点触发由 `framework/news.check()` 完成（挂在 `BaseMode.run()` 与主菜单循环），设备停在任意界面（含主菜单）整点自动播报；`modes/news.py` 只做标题浏览与手动播报。
2. **播报页零文字（v1.5.1 确立，v1.6 维持）**：音频播报期间屏幕只显示**新闻红主题动效**——红色横幅（直播点 500ms 闪烁 + 标题 + 档期）+ 中央喇叭帧动画（v1.6.2：Tabler 喇叭图标四档声波 0→3→0 轮播，按已播秒数 1s/帧）+ 已播时长 + 琥珀色进度条，不显示播报稿/标题等文字内容。
3. **音频路线（官方手册 v2026-09 对齐）**：平台 payload 的 `audio_url` 本身即指向 WAV（`/media/news_audio/latest.wav`，24kHz/16bit/单声道 PCM，约 8MB/档）。**v1.9 双路**：SD 卡已挂载（`framework/sdcard.mounted()`）且 RTC 日期有效 → 先分块落盘 `/sd/music/news_YYYYMMDD_HH.wav`（8KB/块，不整档进 RAM，下载期间播报页显示「SD缓存中」+ 字节进度条，v1.9.2 起中央动画区为**下载图标帧**而非喇叭帧——喇叭帧语义是"播放中"，下载期间屏显喇叭却无声会误导用户）再从文件播放，同档重复播报免下载直接复用；SD 未挂载 / RTC 无效 / 落盘失败 → 维持**边下边播**（流式，不落盘）。两路播放失败均自动降级为纯文字翻页 + 蜂鸣提示（唯一显示文字的路径）。
4. **SD 存档保留一天（v1.9）**：文件按「日期_时段」命名（时段优先解析 payload `hour_label` 如"15点"→15，异常回退本地小时）；每次落盘成功与打开回听列表时自动清理非当日 `news_*.wav`，占用上限约 8MB×14 档≈112MB/天；**今日回听**：新闻模式 A 翻页循环末页为今日回听页，可选当日任一已存档时段回听（`replay(hour)` 阻塞接管，复用播报页 UI，进度条总时长按文件大小÷48KB/s 估算）。
5. **Web 可配**：自动播报总开关（滑动开关）、整点档位勾选（8×2 网格单数字小圆角，7~22 点，档期外弱化）、音量、立即播报（设备播出）与立即获取（拉取当档标题+可看可试听 WAV，核对 API 是否正常）均在 Web「云服务」页签；设备端也可手动播报。
6. **按键遵循 2.4 规范**：内容浏览类（A=翻页/下一项、B=主操作、C=退出/返回），无长按。
7. **音频不可用环境安全降级**：`machine.I2S` 缺失（PC 仿真/无音频档案设备）时播报自动退化为文字模式，不抛异常；SD 路径全套逻辑 try/except 包裹，`sdcard` 导入失败等同未挂载。

## 二、页面结构与导航

```
主菜单 --B--> 整点新闻(标题浏览页, 默认)
                |B=立即播报(阻塞接管, 整屏切到播报页, 播完返回本页整帧重绘)
                |A=翻页循环(末页后进入今日回听页, 回听页 A 再回标题第1页)
                C=退出模式
标题浏览页 --A(末页)--> 今日回听页(v1.9)
                |B=回听选中时段(阻塞接管, 播完返回本页整帧重绘)
                C=返回标题浏览页第1页
(全局) 任意界面/主菜单 --整点到点--> 播报页(接管) --播完/任意键--> 原界面整帧重绘
播报页内部: 正在拉取 → 正在准备 → [SD挂载:SD缓存中(下载图标帧, v1.9.2)] → 正在播报(喇叭帧动画+文件/流播/文字降级) → 收尾页(1.2s)
```

## 五、后台服务 / 业务规则

| 服务 | 行为 |
|------|------|
| 整点检测（`news.check()`，每帧） | RTC 分钟沿比较 + **5 分钟回看补漏**（阻塞操作跳过秒沿不漏播）；`"日-时"` 指纹防止回看窗口内重复播；手动请求标志优先于一切开关 |
| 自动播报条件 | `news.enabled == True` 且当前整点档 ∈ `news.hours`（默认 9~22 共 14 档，平台档期每日 9:00~22:00，服务端每小时 :55 预生成） |
| 播报流程 | `cloud.fetch_json("news_hourly")` 取档（**取数失败重试，v1.8.3**：网络类失败 `网络失败`/`云服务异常` 屏显「10秒后重试」等 10s（`_FETCH_RETRY_MS`）自动重取一次，任意键提前放弃；业务类错误（未订阅/错误码/暂无数据）10s 后不会变，不重试直接进失败页；重试后仍失败才进「播报失败」页）→ GET `script_url` 预取播报稿（≤3000 字节，仅供降级）→ 按 `_resolve_wav_url` 解析 WAV 地址（官方 `audio_url` 即 `.wav`）→ **v1.9 双路播放编排 `_play_wav()`**：SD 挂载+RTC 有效 → 落盘下载（`_download_wav_to_sd`，8KB 块，每块回调字节进度并轮询按键；下载期「SD缓存中」页显示**下载图标帧**，v1.9.2）→ 从文件播（`_play_file_wav`）；否则/失败 → 在线流式 `_stream_wav`（现状路径）→ `framework/audio.play_wav` 块间轮询按键可打断；播放中屏幕仅红横幅（直播点闪烁）+ 喇叭帧动画 + 已播时长 + 进度条（共用回调工厂 `_make_spk_prog`，`on_progress` 逐块驱动） |

业务规则（音频地址解析，v2.3：mp3 直连）——`_resolve_audio_url()` 返回 `(url, 格式)`，优先级：
① 兼容字段 `audio_wav_url`（平台显式指定 WAV 时尊重之）→ ② `audio_url` 以 `.wav` 结尾（**官方现状，直接使用**）→ ③ `audio_url` 以 `.mp3` 结尾 → **MP3 直连**（固件需含 mp3dec 模块，mp129-romfont-mp3dec 起；网络负载仅 WAV 的 1/8~1/24，边下边播/SD 存档/回听全链路支持，SD 存档扩展名随格式为 `.mp3`）→ ④ `script_url`(.txt) 同目录 `latest.wav` 推断 → ⑤ 旧固件（无解码器）`audio_url` 的 `.mp3` 替换为 `.wav`（v1.9 行为，零变化）。③ 排在 ④ 之前是刻意的：否则探测会永远抢先命中 latest.wav 导致 mp3 永不生效。
解析失败走文字降级（串口 `[NEWS] audio(wav|mp3): <url> / audio unavailable / [AUDIO] ...` 可查）。播放分派按格式/扩展名：`.mp3` → `audio.play_mp3`，`.wav` → `audio.play_wav`；回听时长估算 WAV 按 48KB/s、MP3 按 16KB/s（128kbps 假设，仅供列表展示，播放中进度为真实解码秒数）。
业务规则（媒体 URL 拼接）：payload 中 `audio_url`/`script_url` 为站内相对路径，与 `settings.cloud.endpoint` 拼接后普通 GET 下载（平台约定媒体路径无需设备鉴权头）；已是完整 http(s) URL 则直接使用。
