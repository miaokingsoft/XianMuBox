# 本机设置模式（Settings）功能文档

> 模块路径：`src/modes/settings.py`（`SettingsMode`）
> 关联资源：`font/hz_24x24.mpy`（中文）、`font/sy_32x32.mpy`（SN/激活码大字，延迟加载）、`framework/http_server.py`（HTTP 服务启停/轮询，延迟导入）、`framework/qrcode.py`（URL 二维码矩阵编码，延迟导入）、`framework/wifi.py`（连接状态与重连）、`framework/cloud.py`（云平台状态/激活码轮询/手动激活，延迟导入）、`framework/provision.py`（WiFi 配网服务，延迟导入）
> 配置文件：`settings.json → brightness` / `http_port` / `wifi` / `cloud`（读写经 `framework/settings.py`；cloud 的 activation_key/model 出厂固化，设备端与 Web 均不展示）
> 构建绑定：`profiles/*.json → {"id": "settings", "module": "modes.settings", "class": "SettingsMode"}`（full/minimal 均含）
> 最近更新：2026-09-07（新增「WiFi配网」设置项，进入 SoftAP 热点配网页，详见 [WiFi配网功能文档](WiFi配网功能文档.md)）

---

## 一、功能概述

设备端本机设置：iOS 风格卡片列表，8 个设置项，列表内直接操作，配合信息弹窗与二次确认弹窗完成交互。

1. **列表内直改**：亮度为 B 键循环，改完即持久化到 settings.json；HTTP 服务点击进入二维码子页，页内 B 键开关服务；
2. **弹窗体系**：160px 居中信息弹窗（约 2s 自动关闭）+ 恢复出厂二次确认弹窗；
3. **内存友好**：`http_server` 模块（socket+json，约 16KB）延迟到 `enter()` 的 `gc.collect()` 之后才导入刷新状态，避免 `__init__` 时内存碎片不足；`framework/qrcode` 同样在使用时才导入；
4. **完整设置闭环**：WiFi 查看与连接、亮度、HTTP 服务在设备端可完成；API Key/闹钟/天气等复杂编辑经 HTTP 服务二维码扫码进入 Web 配置页；云平台绑定收敛到「云端激活」子页一站完成（激活密钥出厂固化，零配置）。
5. **时区固定**：时区不再提供设置项，全设备固定北京时间 UTC+8（NTP 同步后按 +8h 修正 RTC，设备端与 Web 端一致）。

## 二、页面结构与导航

```
设置列表(8项) --B--> 各设置项动作
  ├─ 无线网络: 已连接 → IP 信息弹窗(2s 自动关) / 未连接 → WiFi 连接动画子页(任意键取消)
  ├─ WiFi配网 → SoftAP 热点配网页(阻塞式: 二维码/帮助页切换 + 连接状态行, 详见 WiFi配网功能文档)
  ├─ HTTP服务: 已连网 → 二维码子页(阻塞式: 扫码访问 URL, B 开关服务, A/C 返回)
  │            未连网 → "Waiting" 等待弹窗(轮询连上自动启动, 10s 超时)
  ├─ 云端激活 → 云端激活子页(阻塞式: 状态/大字SN/激活码 + 10s 轮询, B 手动激活, A/C 返回)
  ├─ 关于本机 → 版本信息弹窗
  └─ 恢复出厂 → 确认弹窗(B 再按一次执行, 5s 超时取消) → machine.reset()
"退出"项 B → 返回主菜单
弹窗/子页内: B=确认, A/C=取消
```

## 三、按键表（全模块一张表）

| 页面 | A | B | C |
|------|---|---|---|
| 设置列表 | 选中项上移 | 执行当前项 | 选中项下移 |
| 信息弹窗 | 取消（关闭） | 确认（关闭） | 取消（关闭） |
| 恢复出厂确认弹窗 | 取消 | 再按一次=执行重启 | 取消（5s 超时自动取消） |
| WiFi 连接动画子页 | 取消连接 | 取消连接 | 取消连接（任意键取消） |
| WiFi 配网页（热点） | 二维码页/帮助页切换 | 用已存凭据重试连接 | 退出配网（收摊热点/DNS/HTTP） |
| HTTP 二维码子页 | 返回列表 | 开/停服务（启动高音 / 停止低音，状态行局部重绘） | 返回列表 |
| 云端激活子页 | 返回列表 | 手动激活（阻塞请求约 1~10s，底部结果提示） | 返回列表 |

- 菜单/列表类页面，遵循按键统一规范（A 上移 / B 确认 / C 下移，退出走"退出"项）；无长按手势。

## 四、设置项明细（8 项）

| # | 设置项 | B 键行为 | 持久化 |
|---|--------|---------|--------|
| 1 | 无线网络 | 已连接：弹窗显示 SSID/IP（2s 自动关）；未连接：进入连接动画子页（信号弧图标逐级点亮 + SSID + Connecting 文案；成功显示 OK+IP 约 1.5s 后自动回列表，失败显示 Failed 并打印诊断日志） | 连接结果写 `settings.json → wifi` |
| 2 | WiFi配网 | 进入 SoftAP 热点配网页（`framework/provision.run_provision_page()`，阻塞式子页）：设备开热点 `XianMuBox-<SN末4位>`，屏显二维码 + 热点名；A 切帮助页（三步指引），B 重试已存凭据，C 退出；手机连接热点自动弹配网页（或扫码），提交后设备屏同步 连接中/成功(OK+IP 自动退出)/失败 状态；成功回列表后弹 WiFi Connected 弹窗 | 新凭据写 `settings.json → wifi`（插首/去重/上限 5）；详见 [WiFi配网功能文档](WiFi配网功能文档.md) |
| 3 | 屏幕亮度 | 循环 25% / 50% / 75% / 100%（PWM duty 256~1023，即时生效，蜂鸣音调随档位递增） | `settings.json → brightness` |
| 4 | HTTP 服务 | 进入二维码子页：WiFi 已连接时确保服务启动（未运行则自动启动），全屏显示 Web 页 URL 二维码（标题「扫码访问」+ 白底黑码居中 + 青色 URL 行 + 绿 Running/红 Stopped 状态行 + 底部 `B:ON/OFF A/C:BACK`）；URL 端口 80 省略、非 80 带 `:端口`；页内 B=开/停服务，A/C 返回。未连网时不进子页，弹"Waiting"等待（10s 超时），loop 轮询连上后自动启动并回列表 | 运行态（不落盘）；子页阻塞期间由子页循环每帧 `poll_http_server()` 处理请求，列表态由 loop 每帧 `_poll_http()` 处理 |
| 5 | 云端激活 | 进入云端激活子页（绑定流程唯一设备端入口）：状态行（已激活/待绑定/未激活/等待校时/已停用/失败+错误码）+ 大字内容 + 底部 `B:ACTIVATE A/C:BACK`。中区按状态切换：**待绑定**=激活码 32px 大字（琥珀色）+ 有效期 EXP + 「平台网页输入」提示 + SN 小字；**其余**=设备号 SN 32px 大字两行（隔屏可读，供用户抄到平台网页发起绑定）+ 已激活时附平台域名/最近心跳两行。打开期间每 10s 调 `cloud.poll_pending()` 轮询激活码（进页立即拉一次，接住先在网页发起的绑定），新码到达双音提示；码超平台 5 分钟有效期自动消失。B=手动激活（`activate_now()`，Token 轮换）。列表项 detail 为 ASCII 状态摘要（OK/BIND/NoKey/NoNTP/OFF/Idle/E+错误码） | 激活结果 Token 仅存 RAM；激活码由云端经心跳/兜底接口下发（`settings.json → cloud` 仅 enabled 可改，密钥/型号出厂固化）。SN 以 `machine.unique_id()` 派生值为唯一权威（可查不可改：`settings.json → project.device_sn` 仅展示缓存，篡改在 `get_device_sn()` 读取时自动纠偏，Web POST 写入被 `_validate_project` 丢弃） |
| 6 | 关于本机 | 弹窗显示 XianMuBox 固件版本（运行时读 `config.FW_VERSION`，如 `XianMuBox v1.3.0`）/ MicroPython 版本 / 空闲内存 | — |
| 7 | 恢复出厂 | 首次按弹"Press B again!"（5s 超时取消），再次按执行 `machine.reset()` 重启 | — |
| 8 | 退出 | `flash_exit()` 返回主菜单 | — |

> 亮度档位修改在模式运行期生效于 PWM；`exit()` 时恢复满亮度，避免下一模式继承低亮度。

## 五、后台服务

| 服务 | 行为 |
|------|------|
| HTTP 请求轮询 | loop 每帧调用 `_poll_http()` 非阻塞处理一个挂起请求（Web 配置页在该模式开启服务期间可用）；HTTP 二维码子页阻塞全局 tick，请求由子页循环内 `poll_http_server()` 接管 |
| WiFi 等待轮询 | HTTP 服务开启时若未连网，loop 中轮询连接状态，10s 内连上自动启动服务 |
| 激活码子页轮询 | 云端激活子页内每 10s 调 `cloud.poll_pending()`（全局 tick 被阻塞子页挂起，由子页接管；服务端返回空指令列表即清空本地激活码信箱） |

## 六、性能与资源

- `http_server` 延迟导入：`__init__` 只置标志，`enter()` 在 `gc.collect()` 后刷新 HTTP 状态详情，防大模块编译压垮内存碎片；
- `framework/qrcode.py` 纯 MicroPython 二维码编码器（byte 模式 V1~V3、ECC M、固定 mask 0，矩阵四边自带 2 模块空白），仅进入二维码子页时导入；URL 场景 22~30 字节，V2（29×29）~V3（33×33）矩阵，scale=5 绘制约 145~165px 见方，`get_matrix()` 一次算完约几十毫秒；正确性经 OpenCV 解码与参考库矩阵比对双重校验（`tools/_check_qrcode.py`）；
- `framework/cloud.py` 同样延迟导入（模块体仅常量与函数定义，导入开销小）；云停用（enabled=false）时 `ready()` 短路，子页仅展示"已停用"状态；
- `font/sy_32x32` 大字字库在子页首次绘制时惰性加载；
- WiFi 信号弧图标的 sin/cos 查表懒加载；
- 列表采用局部重绘（单行卡片重绘），弹窗绘制前后局部刷新。

## 七、数据依赖

| 数据 | 来源 | 缺失表现 |
|------|------|----------|
| WiFi 配置 | `settings.json → wifi`（经 `framework.settings.get_wifi_configs()`） | 连接子页无可用网络 |
| 亮度档位 | `settings.json → brightness`（启动时读入初始档） | 默认 100% |
| 云服务状态/激活码 | `framework/cloud.py → status()` / `get_pending()` / `poll_pending()`（status 纯内存；轮询发起网络请求） | 云停用时子页显示"已停用"；`framework.cloud` 导入失败时列表 detail 保持 "Idle"；NTP 未校时时显示"等待校时"且不轮询 |
| HTTP 服务模块 | `framework/http_server.py`（延迟导入） | 弹窗 "HTTP N/A" |
| 二维码编码器 | `framework/qrcode.py`（进入子页时导入） | 子页显示 "QR ERROR"（URL 超长或编码异常，正常 IP 段不会触发） |
| 蜂鸣器 | `BaseMode.beep()`（buzzer 可为 None） | 无声，不影响功能 |

> 字库依赖：子页全部文案（绑确认输入云心跳已激活校端等）已由全量字库 `font/hanzi_24`（GB2312 6763 字全覆盖，数据嵌固件 romfont）承载，无补字依赖；历史 hz_24x24 追加字流程已废弃（`tools/gen_full_font.py` 全量再生成）。
