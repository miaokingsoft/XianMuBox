# 固件版本履历（闲沐盒子 · 单一事实源）

> 本文档是定制固件的**版本记录中枢**：每次产出新固件，先在此登记（文件名/双归档路径/大小/MD5/模块构成/源码锁定/验证状态），再烧录。构建方法见 `doc/固件构建指南.md`。
>
> **归档惯例（双处 + MD5 一致）**：仓库内 `firmware/release/` 一份 + 工具库 `D:\Mycode\MicroPython\esp32-build\firmware\`（esp32-build）一份，`md5sum` 比对一致才算归档完成。
>
> **上机标识**：REPL 执行 `import mp3dec` 仅在 mp3dec 起的固件可用（可 `mp3dec.version()` 看解码库版本）；romfont 固件可用 `import romfont` 判别。

## 二、mp129-romfont-mp3dec（2026-09-17，现役候选）

- **变更**：在 mp129-romfont 基座上新增第 4 个 user C module **`mp3dec`**——封装 [minimp3](https://github.com/lieff/minimp3)（CC0 公有领域）为逐帧解码模块；框架层 `src/framework/audio.py` 同批新增通用 `play_mp3()`（契约与 `play_wav` 一致）。详见 `doc/框架架构设计文档.md` 第 11 节。
- **模块 API**：`mp3dec.Decoder().feed(buf, out, vol_shift=8) -> (consumed, pcm_len, samples, rate, channels)`；`dec.reset()`；`mp3dec.version()`；`MAX_SAMPLES_PER_FRAME` 常量。
- **构建配方**：`USER_C_MODULES=/work/romfont/micropython.cmake` 单入口；链序 **st7789 → mp3dec**（**构建时临时注释 lvgl 链**，用后恢复——仓库 `firmware/romfont/micropython.cmake` 保留 lvgl include，现役线与储备线共用一个入口、一条注释行切换）。
- **构建踩坑（新增，重要）**：`make clean`（idf.py clean）**保留 CMakeCache.txt 与 CMakeFiles**，对"从链中**移除**模块"（如本版去 lvgl）这类减法，陈旧源清单会残留——moduledefs 仍注册已移除模块，链接报 `undefined reference to mp_module_lvgl`。**必须 `rm -rf build-*` 整目录删除**（等价 `idf.py fullclean`）后再编。增加模块（加法）不受影响。
- **minimp3 版本锁定**：commit `ea99364f61c14656440e8d77e9c233ccf3124633`（master @2026-07-27），本地存档 `firmware/mp3dec/minimp3.h`（含 `MINIMP3_IMPLEMENTATION`），下载走 jsdelivr CDN（`cdn.jsdelivr.net/gh/lieff/minimp3@<commit>/minimp3.h`，GitHub raw 直连不通时的可用通道）。**⚠️ 本地补丁（重下载上游源码不会自带，必须保留）**：`minimp3.h` 的 `mp3dec_decode_frame` 内 `mp3dec_scratch_t scratch` 约 16KB 栈局部，MicroPython ESP32 主任务栈（16KB）装不下，真机首帧解码即触发 FreeRTOS stack canary 复位（2026-09-17 实测）——已加 `MINIMP3_STATIC_SCRATCH` 开关把 scratch 移入 .bss（单线程宿主适配），`mp3dec.c` 定义该宏启用。
- **真机验证记录（2026-09-17 全部通过）**：①`import mp3dec` + `version()` ✅；②`tests/mp3_diag.py` 解码基准 **8.7× realtime**（44.1kHz/mono，232 帧 6.1s 音频 700ms 解完，目标 ≥2×）✅；③`audio.play_mp3` 播 SD 卡 mp3 出声（`(True, "")`，6099ms 播完 6.1s 音频，I2S 节拍精确）✅；④`framework/audio.py`（含 play_mp3）已推送设备 FS ✅；⑤SD 卡挂载/新闻 WAV 存档正常（music 目录当日 13 个存档可见）✅；⑥settings.json 无损（分区表未变，FS 保留）✅。**烧录历史**：首刷版（md5 `e8e0591d…`）存在 stack canary bug（见上），已由 `b854cf6f…` 替换，两者 flash 段差异 2,288B。
- **⚠️ 进下载模式经验**：`machine.bootloader()` 若主机串口句柄未先释放，TinyUSB CDC 会固件级挂死（Windows 报错误 31，Disable/Enable/移除重扫均无法恢复，只能按 RST）。**安全做法**：设备端 `time.sleep(0.8)` 延时后执行 `machine.bootloader()`，主机在延时窗口内关闭串口句柄，1 秒内 1001 端口即出现（参考 esp32-build 用法，本轮实测三次挂死两次成功后确立）。

## 三、版本记录操作规程（此后每次产出新固件）

1. 改动固件模块后在 `doc/固件版本履历.md` 总表**新增一行**（版本标识按 `mp129-<组件链>` 惯例命名），并附独立小节记录变更/配方/锁定/验证清单。
2. 构建产物先落 `firmware/release/`，再复制到 esp32-build `firmware/`（沿 `xianmubox-mp129-<组件链>.bin` 命名），**md5sum 两处比对一致**。
3. 同批更新：`doc/固件构建指南.md`（配方/体积）、README（固件要求/版本历史）、`doc/项目目录结构说明.md`、涉及模块的架构文档章节。
4. 烧录后回填真机验证状态（总表"状态"列）。
