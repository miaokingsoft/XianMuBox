> 版本：v1.4  
> 更新日期：2026-09-02  
> 硬件平台：ESP32 系列 (S3/S2 等)，当前参考硬件为 ESP32-S3 N8R8

## 1. 架构总览

### 1.1 三层插件架构

本框架将系统划分为三个独立层次，每层均为可替换的插件。装配层 `boot.py`（硬件初始化 + 开机动画，完成后立即返回）与 `main.py`（应用主循环）把初始化、菜单、模式分发串联为完整系统。

> ⚠️ MicroPython v1.27+ 在 boot.py 结束后才初始化 USB CDC（[micropython#18581](https://github.com/micropython/micropython/issues/18581)），boot.py 不得内嵌常驻主循环，否则设备 USB 永不激活；本仓库定制固件另在 main.c 中将 `mp_usbd_init()` 恢复至 boot.py 之前执行（双保险）。

```
boot.py (初始化装配) + main.py (应用主循环)
  初始化硬件 → 加载 settings.json → 应用亮度 → 播放开机动画 → NTP/时区 → 显示菜单 → 模式分发
      │              │                  │              │              │             │            │
      ▼              ▼                  ▼              ▼              ▼             ▼            ▼
  framework/hal  framework/settings  PWM(BLK)    boot_animations/   framework/    menus/      modes/
  framework/wifi
```

### 1.2 各层职责

| 层次 | 目录 | 职责 | 可替换性 |
|------|------|------|---------|
| 平台层 | `framework/` | 硬件抽象、颜色调色板、WiFi、settings 统一读写、HTTP 配置服务 | 通用基础（跨项目复用） |
| Boot 插件 | `boot_animations/` | 开机视觉表演，一次性的动画效果 | 可替换：Matrix / 简约 / 跳过 |
| Menu 插件 | `menus/` | 功能导航界面，返回 MODE_ID | 可替换：列表 / 轮播 / 网格 |
| Mode 插件 | `modes/` | 具体功能实现，独立的 UI+逻辑 | 可自由组合：增删任意功能 |
| 配置层 | `config.py` + `app_config.py` + `settings.json` | 硬件配置 / 应用编排 / 敏感数据 三层分离 | 适配不同硬件时改 `config.py` |

## 2. 接口规范

### 2.1 Boot 插件接口

```python
def play(display, buzzer):
    """
    播放开机动画。
    display:  ST7789 对象（已初始化，由 framework/hal.py 创建）
    buzzer:   Buzzer 实例
    返回:     None
    """
```

实现示例参见 `boot_animations/matrix.py`。开机动画可选用 `framework.wifi.WiFiConnector` 在保持 UI 流畅的同时并发连接 WiFi。

### 2.2 Menu 插件接口

```python
def run_menu(display, buttons, buzzer=None) -> str:
    """
    显示菜单并等待用户选择。
    display:  ST7789 对象
    buttons:  Buttons 实例（来自 framework/hal.py）
    buzzer:   Buzzer 实例或 None
    返回:     MODE_ID 字符串（与 app_config.py MENU_ITEMS 中的 id 一致）
    """
```

实现示例参见 `menus/list.py`。

### 2.3 Mode 插件接口（BaseMode）

所有功能模式必须继承 BaseMode 并实现以下方法：

```python
class XxxMode(BaseMode):
    MODE_ID = "xxx"    # 类属性，与 app_config.py 和 registry.py 中的 id 一致

    def __init__(self, display, buttons, buzzer=None):
        super().__init__(display, buttons, buzzer)
        # 可在此初始化模式专有状态

    def enter(self):
        """进入模式：清屏 + 首次绘制（必须实现）"""

    def loop(self) -> bool:
        """主循环：处理按钮，返回 True 继续，False 退出（必须实现）"""

    def exit(self):
        """退出模式：资源清理（可选重写）"""
```

BaseMode 提供以下工具方法：

| 方法 | 用途 |
|------|------|
| `_scan_with_timing()` | 按钮扫描 + 三键长按检测，返回 (up, sel, down, b_long, a_long, c_long) |
| `draw_wifi_bar(connected, ip)` | 顶部 WiFi 状态条 |
| `draw_card(x, y, w, h, selected)` | iOS 风格卡片 |
| `flash_exit()` | 闪白退出反馈 + 蜂鸣器提示 |
| `beep(freq, ms)` | 蜂鸣器短音 |

> `run()` 主循环每帧还会夹带两个全局服务检查：`framework.alarm.check()`（全局闹钟，v1.3）与 `framework.cloud` 的 `tick()`（云平台心跳调度，v1.4，`CLOUD_TICK=False` 的模式豁免），模式代码无感知；闹钟到点时响铃页阻塞式接管，停止后由宿主模式 `enter()` 整页重绘恢复。云端激活码 **不做** 全屏接管（v1.4.1 起），仅由本机设置「云端激活」子页轮询展示。详见 2.7 / 2.8 节。

### 2.4 按键统一规范（所有页面必须遵循）

> 2026-08-30 确立。原则：**短按为主、不用长按**（长按易误判，唯一例外见下）。

**内容浏览类页面**（项目仪表、模型余额、股票、自媒统计、背单词等）：

| 按键 | 功能 |
|------|------|
| A 短按 | 翻页（向后循环到下一张 / 下一项） |
| B 短按 | 主操作（刷新 / 确认） |
| C 短按 | 退出返回主菜单（`flash_exit()`） |

**菜单/列表类页面**（主菜单、本机设置、各模式子菜单）：

| 按键 | 功能 |
|------|------|
| A 短按 | 选中项上移 |
| B 短按 | 确认 / 执行 |
| C 短按 | 选中项下移 |

- 退出方式：内容浏览类 = C 短按；菜单/列表类 = 页面内"退出"菜单项。
- **不新增任何长按功能**。当前唯一例外：控刷视频(swipe) 的 A 长按 = 切换 BLE 设备（仅非运行态）。
- 已知遗留：摩斯电码各子功能（移植套件）内部仍用 B 长按=返回子菜单，待后续统一。

**按键采集机制**（2026-09-03 加固，`framework/hal.py` 统一实现）：

- **双路边沿检测**：三键注册 `Pin.irq`（双沿），按下沿在 ISR 中置事件标志+时间戳（零分配）；主循环 `scan()/scan_timed()` 轮询采样，边沿 = 采样比较 **OR** IRQ 锁存事件，两路互去重。主循环被网络等长操作阻塞期间完成的按压由硬件边沿锁存，恢复后补报，**不再丢失**。
- **30ms 消抖**（`hal.DEBOUNCE_MS`）：IRQ 事件须距按下 ≥30ms 才确认；距最近释放沿 <30ms 的下降沿判为释放抖动直接忽略（消除"按一次跳两格"）。
- **时长校验**（`hal.MIN_PRESS_MS` = 15ms，2026-09-03 补）：消费锁存事件时若引脚已回高，还须实测低电平段 ≥15ms 才确认——EMI 毛刺（µs 级）与释放余颤（几 ms）的瞬闭段被丢弃，否则会在 30ms 后被当正常事件上报（单按双触发的根源）。
- **统一扫描入口**：`scan()`（返回 up/sel/down 三元）与 `scan_timed()`（另附当前电平 a/b/c，供长按计时）是全项目唯一的边沿来源；`BaseMode._scan_with_timing()`、闹钟响铃循环、摩斯 ButtonAdapter 均已收敛到该入口。**新增页面不得自行 `read_raw()` 比较边沿**，长按检测用 `scan_timed()` 的电平即可。
- **模式交接防幻影**：进入新页面/闹钟响铃前调 `buttons.clear_events()` 丢弃残留事件（`words_main.enter()`、`ButtonAdapter.reset()`、`alarm._ring()` 均已接入）。
- **配套帧周期优化**：HTTP 服务轮询改 `setblocking(False)`（原每帧固定吞 50ms）；云端心跳单请求超时 10s→5s；时钟模式帧尾 200ms→50ms；菜单选中闪烁与设置页导航驻留缩短。

### 2.5 生命周期调用时序

```
main.py 主循环:
  ┌─ menu.run_menu() ─────────────────────────→ 返回 MODE_ID
  │
  ├─ registry.dispatch(mode_id):
  │     1. __import__ lazy load mode module
  │     2. mode = XxxMode(display, buttons, buzzer)  ← __init__
  │     3. mode.enter()        ← 首次绘制
  │     4. loop:
  │          mode.loop() → True  → continue
  │          mode.loop() → False → break (C 短按 / 菜单退出项返回)
  │     5. mode.exit()         ← 清理资源
  │     6. gc.collect()        ← 内存回收
  │
  └─ back to menu ─────────────────────────────
```

### 2.6 装配层（boot.py）详细职责

`boot.py` 不仅是"一行 import"，而是完整装配链：

1. **硬件初始化**：`init_display()` + `Buzzer` + `Buttons`
2. **加载 settings.json**：`framework.settings.load_settings()`（首次启动写默认值）
3. **应用亮度档位**：根据 `settings["brightness"]`（25/50/75/100）设置 PWM duty
4. **开机动画**：调用 `boot_animations.<profile>.play(display, buzzer)`（可在动画期间用 `WiFiConnector` 并发连 WiFi）
5. **NTP + 时区**：若 WiFi 已连，尝试 `ntptime.settime()`（失败自动重试，最多 3 次，间隔 500ms）；成功后回调 boot.py 注入的 `tz_apply` 把 RTC 从 UTC 修正为北京时间 UTC+8（时区不再读配置；RTC 无掉电保持，此处失败由网络时钟模式 60s 周期重同步兜底）
6. **主菜单 + 模式循环**：见 2.4

### 2.7 全局闹钟服务（framework/alarm.py，v1.3 新增）

闹钟是**框架级服务**而非某个模式的功能：设备开机后，任意功能模式运行中闹钟到点即接管屏幕进入响铃页；任意按键停止，60s 自动静默。

- **接入点**：`BaseMode.run()` 主循环每帧调用 `alarm.check(display, buttons, ...)`，模式代码零侵入。
- **配置来源**：`settings.json` 的 `alarms` 节点（恒 3 组），Web 配置页"闹钟"页签编辑，设备端网络时钟模式的闹钟列表页可查看/快速开关。
- **触发机制**：RTC 分钟沿匹配 + 5 分钟回看补漏（秒沿被阻塞操作跳过时不漏响）；星期匹配用 Zeller 日期计算，不依赖 RTC weekday 字段。
- **热加载**：每秒沿直接读 settings 模块缓存，Web 保存后 ≤1s 生效；单次闹钟（`days` 为空列表）触发后自动关闭并落盘。
- **内存友好**：`check()` 常驻每帧但只做分钟变化比较，开销极小。

### 2.8 全局云服务（framework/cloud.py，v1.4 新增，v1.4.1 重构绑定流程）

云平台客户端是**框架级服务**：闲沐盒子 API 服务平台（默认 `https://api.wwzu.com`）的设备侧统一接入层，负责激活换 Token、心跳调度、绑定激活码与任意数据源统一取数。

- **Token 生命周期**：开机自动激活（出厂固化 `activation_key` 换 `device_token`）→ 之后心跳/取数复用同一 Token（仅存 RAM，不落盘不进日志）→ 仅设备重启 / 收到 40102（解绑、管理员重置、他处重复激活导致吊销）/ 手动「立即激活」时重新获取。**绑定**（确认码流程）是设备与平台用户账号的关联，不发放 Token；未绑定取数返回 40101，未订阅数据源返回 40302。
- **接入点**：`BaseMode.run()` 每帧调用 `cloud.tick()`（到期补激活/心跳）；`menus/list.py` 空闲循环同样接入，设备停在菜单不留盲区。时序敏感模式可设类属性 `CLOUD_TICK = False` 豁免（当前仅 `SwipeMode`，BLE 自动滑动不能容忍请求阻塞）。
- **绑定流程（v1.4.1 起，设置页中心制）**：绑定激活码不再全屏接管。平台网页（用户中心「我的设备」）输入设备 SN 发起绑定后，`bind_confirm` 指令经心跳 `pending_ops` 或兜底 `GET /device/pending`（响应键 `ops`，兼容读 `pending_ops`）下发；设备端唯一展示入口为本机设置「云端激活」子页——打开期间每 10s 调 `poll_pending()` 轮询（全局 tick 被阻塞子页挂起），收到激活码大字展示并提示「平台网页输入」，用户 5 分钟内回填网页完成绑定；服务端返回空指令列表即清空本地信箱，激活码超 5 分钟本地计时自动失效。
- **激活/心跳**：首次开机延迟 8s 上报（避开联网风暴）；心跳间隔按服务端 `next_interval` 调度（默认 600s）；40102 Token 吊销自动回退出厂密钥重激活；网络失败指数退避 30s 起倍增封顶 30min；40104（SN 未登记/密钥错）与 40301（被禁用）按配置类错误长退避。
- **请求前置**：`cloud.enabled` 开启 + `activation_key` 非空（出厂固化默认值，空值自动回退）+ RTC 年份 ≥ 2026（NTP 已校时，平台 TLS 要求正确时钟；NTP 主机固定 `ntp.aliyun.com`）+ WiFi 已连接；不满足不发请求。
- **统一取数（新功能接入方法）**：

```python
from framework.cloud import fetch_json
code, data = fetch_json("hot_weibo")                        # 无参源
code, data = fetch_json("weather_basic", {"city": "深圳"})   # 带参源，自动拼 query
# code == 0: 渲染 data["payload"]（含 updated_at/stale/source_name）
```

### 2.9 全局整点新闻播报服务（framework/news.py + framework/audio.py，v1.5 新增）

整点新闻播报是**框架级服务**（与 2.7 闹钟同机制）：每日 9:00~22:00 共 14 个整点档，设备停在任意界面（含主菜单）到点即接管屏幕进入播报页——拉取闲沐云平台 `news_hourly` 数据源当档 payload，经 MAX98357A 功放流式播放当档 WAV 音频；**播报期间屏幕只显示新闻红主题动效（红横幅直播点闪烁 + 喇叭帧动画 + 已播时长 + 进度条），不显示文字内容（v1.5.1 确立，v1.6 维持）**；播完或任意键停止后由宿主模式 `enter()` 整帧重绘还原。

- **接入点**：`BaseMode.run()` 与 `menus/list.py` 空闲循环每帧调用 `news.check(display, buttons, buzzer)`；命中即阻塞播报（返回 True，宿主重绘）。仿 2.7 闹钟的 `_XXX_SVC` 惰性加载模式。
- **音频层（framework/audio.py）**：`machine.I2S` TX 封装（Philips 时序，`machine.I2S` 缺失时全接口安全降级 no-op）；**I2S 固定以 `STEREO` 打开、每个采样复制成左右相同帧写入（v1.6.1）**——S3 + MicroPython v1.20 固件的 MONO 档存在采样左右交替错位 BUG（micropython#11635），MAX98357A（SD=3V3 只出左声道）会丢失一半采样致半速变调，该绕过对 v1.22+ 新 I2S 驱动固件同样正确；**流播抗卡顿（v1.6.1）**：`_IBUF` 32KB（≈340ms 余量吸收网络/TLS 抖动）、`_CHUNK` 8KB、`wifi.py` 连接即关省电（modem sleep 的 DTIM 延迟尖峰是卡顿源之一）；采样解析固定用 `struct.unpack`——勿用 `array('h', bytes/memoryview)` 直读，部分固件的 array 构造器把缓冲按字节值逐个迭代，等于把字节流当样本输出（幅度 ≈1/128 的沙沙噪声，v1.6.1 真机踩坑）；`play_wav()` 边下边播——调用方传 `r.raw.read` 供数、`is_cancelled` 每块（约 170ms）轮询按键、`on_progress` 回调秒数；WAV 头自适应采样率/声道（仅 16bit PCM，立体声取左声道）；数字音量 = 采样右移 0~8 位（`volume` 0~100，约 6dB 步进），MAX98357A GAIN 引脚保持出厂 9dB；I2S 外设按次 init/deinit 不常驻 DMA 内存。引脚常量在设备档案（S3：`I2S_BCLK=38 / I2S_LRC=39 / I2S_DIN=40`，v1.9 由 15/16/14 调整，经 config.py `getattr` 透出，无音频档案设备为 None）。**MP3 播放（2026-09-17 新增）**：`play_mp3(read_fn, volume, is_cancelled, on_progress)` 参数契约与 `play_wav` 完全一致（`read_fn` 供数 / 每帧轮询打断 / 整秒进度回调），解码在固件 `mp3dec` C 模块（minimp3）内逐帧完成——音量右移 + 单声道复制立体声都在 C 侧，Python 只维护滑窗供数与 I2S 写入；I2S 采样率取首个成功解码帧；固件无 mp3dec 时返回 `(False, "no decoder")`（`mp3_supported()` 可探测），新闻播报等调用方可据此降级；返回 err 语义同 play_wav（`cancelled/no audio/no decoder/bad mp3/io/memory`）。解码契约与滑窗细节见第 11 节。**播放收尾排空（v1.5.1，2026-09-19）**：`I2S.write()` 返回只代表数据已拷入 `_IBUF` 64KB 前置缓冲（稳态常驻约 0.3~0.7s 尾音），此前正常播完立即 `deinit` 会把每条音频最后一小段砍掉（听老故事每页尾句被切首曝；电台长段/新闻结尾不敏感故未察觉）——现 `play_wav/play_mp3` 正常播完路径经 `_drain_i2s(rate, ch)` 按缓冲字节量折算时长（+60ms 余量，上限 1s）等待播完再释放；打断路径不排空，保持打断即时性。
- **播报页动画（v1.6.2 喇叭素材帧 + v1.9.2 下载素材帧）**：播报/回听中按已播秒数轮播 4 帧 80×80 大端 RGB565 raw（`icons/news_spk_0~3.raw`，Tabler 喇叭图标白色描边 + 三档声波弧线，`tools/gen_speaker_frames.py` 从 SVG 生成 PNG、build 9.1 转 raw；MIT 许可），往返序列 0→3→0（1s/帧），`on_progress` 内 `blit_buffer` 单帧约 3-5ms 且帧未切换时零绘制；raw 首次使用读入缓存（4 帧共 80KB），缺失安全降级为纯黑。**SD 落盘下载期（v1.9.2）改用下载图标帧**（`icons/news_dl_0~2.raw`，Tabler download 箭头落托盘三档高度，`tools/gen_download_frames.py` 生成，`_DL_SEQ=(0,1,2,1)` 350ms/帧时间驱动）——喇叭帧语义是"播放中"，下载约 1 分钟/档期间屏显喇叭却无声会误导用户，缓存/降级策略同喇叭帧。历史：v1.6 程序绘制均衡器（12 柱镜像声波，整区清屏+全量重画 ≈90KB 像素/帧）v1.6.1 改差量重绘（≈30ms/帧）均因绘制占实时预算比例过高（流播卡顿源之一，`_DBG` 真机实测）弃用；更早的 `icons/news_bcast_0~3` 四帧方案（v1.5.1）即本方案前身，v1.6 删除、v1.6.2 以新素材恢复该路线。红横幅直播点 500ms 闪烁、状态行右侧 `MM:SS` 已播时长、琥珀色进度条同回调刷新。
- **触发机制**：RTC 分钟沿匹配 + 5 分钟回看补漏（仿闹钟），**`"日-时"` 指纹**防止回看窗口内同档重复播；手动播报 `request_play()`（Web 触发）/`play_now()`（新闻模式 B 键，阻塞直呼）优先于时段与开关。
- **触发条件**：`settings.news.enabled == True` 且整点档 ∈ `news.hours`（Web「云服务」页签配置，7~22 点勾选，热加载）。
- **播报流程与降级链**：`cloud.fetch_json("news_hourly")` 取档（错误码语义透传：40302 未订阅等）→ GET `script_url` 播报稿预取（≤3000 字节，仅供降级展示）→ GET 音频播放（官方：`audio_url` 即 `/media/news_audio/latest.wav`，24kHz/16bit/单声道，约 8MB/档；**v2.3 mp3 直连**：`audio_url` 为 `.mp3` 时直接流式解码播放，流量仅 WAV 的 1/8~1/24，旧固件自动回退原 `.mp3→.wav` 换后缀链；**v1.9 双路编排 `_play_audio()`**：SD 挂载且 RTC 有效 → 分块落盘 `/sd/music/news_YYYYMMDD_HH.mp3|.wav`（扩展名随音源格式，保留一天自动清理，下载期「SD缓存中」页屏显下载图标帧，v1.9.2）再从文件播（按扩展名分派 play_mp3/play_wav，历史 wav 存档兼容），同档复用免重下，下载中断=删除半截按「已停止」收尾；未挂载/失败 → 原在线流式）→ 音频下载/解析失败时蜂鸣提示后进入文字翻页降级（每页 4s 自动滚动，唯一显示文字的路径）；I2S 不可用环境直接文字模式。**音频地址解析（`_resolve_audio_url`，v2.3）**：① `audio_wav_url` 兼容字段 → ② `audio_url` 以 `.wav` 结尾直接使用（官方现状）→ ③ `audio_url` 以 `.mp3` 结尾且固件带解码器 → mp3 直连 → ④ `script_url` 同目录 `latest.wav` 推断 → ⑤ 旧固件 `audio_url` 的 `.mp3`→`.wav`；失败原因经串口 `[NEWS]/[AUDIO]` 诊断。
- **SD 存档与回听 API（v1.9，依赖 2.10 sdcard）**：`sd_mounted()` 查询挂载态；`replay_list()` 返回当日存档时段升序列表（顺带清理非当日文件）；`replay(hour, display, buttons)` 阻塞接管回听（复用播报页 UI 与共用进度回调工厂 `_make_spk_prog`，任意键停止），供新闻模式"今日回听"页（A 翻页循环末页）调用；细节见 `doc/整点新闻播报模式功能文档.md` v1.9。
- **结果缓存**：最近一次播报结果驻留 RAM（`news.status()`），供新闻模式页免联网复用与 `GET /api/news/status` 查询。
- **平台侧状态（官方手册 v2026-09）**：WAV 已随 `audio_url` 上线（`latest.wav`，24kHz/16bit/单声道，约 8MB/档），无需额外字段；设备需在平台门户订阅 `news_hourly`（未订阅 40302）。

### 2.10 SD 卡挂载服务（framework/sdcard.py，v1.9 新增）

- **职责**：TF 卡（SPI 模式）开机挂载到 `/sd`，供动画素材 / 音频 / 数据记录等用途；模式层经 `mount_point()` 取挂载路径，勿硬编码。**已接入使用方**：framework/news.py（v1.9 新闻播报 WAV 存档 `/sd/music/news_YYYYMMDD_HH.wav` + 今日回听，未挂载自动回退在线流式）。
- **接口**：`mount() -> bool`（幂等；`machine.SDCard(slot=2, sck/mosi/miso/cs 显式引脚)` 走独立 SPI(2) 总线，20MHz 失败自动降 10MHz 重试一次）/ `umount()`（卸载并释放 SPI 外设，幂等）/ `mounted()` / `mount_point()`。
- **引脚**：设备档案 `SD_SCK=18 / SD_MOSI=17 / SD_MISO=13 / SD_CS=1`（经 config.py `getattr` 透出；无 SD 档案设备为 None，`mount()` 直接返回 False）。

### 2.11 非阻塞 HTTP GET 状态机（framework/http_nb.py，v2.2 新增；v2.3 增 get_text_blocking）

- **职责**：供功能模式在 `loop()` 里逐帧 `tick()` 推进的 HTTP GET 客户端，根治"等待网络时 UI 动画冻结"。纯 `http://` 走非阻塞 socket + `uselect.poll` 状态机（DNS→连接→发送→接收→解析；接收按 512B×4 次/帧限速，单帧预算约 20ms）；`https://` 无法分步（TLS 握手阻塞），`start()` 直接返回 `BLOCK`，调用方走 `get_json_blocking()` 阻塞回退，非 JSON 响应（腾讯行情 `v_xxx="..."`）用 `get_text_blocking()` 取原始字节。**已接入使用方**：modes/stock.py（v2.2 持仓/腾讯行情/K线三类请求全部非阻塞化；v2.3 起腾讯行情链路追加 `get_text_blocking()` 阻塞兜底——真机非阻塞读取失败时自动自愈，成功后转粘滞阻塞模式，与 mooview 的 `get_json_blocking()` 形成统一兜底范式）。
- **接口**：`Request(url, headers=None, timeout_ms=8000)` → `start()`（DNS 一次性解析，常规 <100ms）/ `tick() -> RUN|DONE|FAIL|BLOCK` / `body()` / `status` / `error` / `close()`；模块级 `get_json_blocking(url, headers=None, timeout_ms=8000) -> (status, dict|None)` 与 `get_text_blocking(url, headers=None, timeout_ms=6000) -> (status, bytes|None)`（urequests 阻塞路径的 JSON / 原始字节两版，均不抛异常）。
- **健壮性**：全程不抛异常（失败统一 FAIL + error 字符串）；响应头解析 Content-Length 与 chunked 两种长度语义（chunked 增量解析，净数据 `_clean` 与原始流 `_body` 分离），`Connection: close` 以 EOF 收尾；**截断一律硬失败**（错误含 `已收/应到` 字节数，如 `truncated 512/2000`——部分 JSON 交给上层只会得到 syntax error，诚实上报由周期刷新自愈）；**接收按"数据可用即连续排空"**（15ms 单帧时间预算，不限 recv 次数——40ms 帧间隔慢读会触发部分服务器在 close 语义下提前关连丢弃未读缓冲，真机 truncated 根因，2026-09-16）；默认发送 `User-Agent` 头（对齐 urequests 请求形态）；响应头 16KB / 响应体 96KB 上限保护；超时统一 `ticks_diff` 判定。
- **移植性**：errno/socket 常量因子移植而异——ESP32 的 `uerrno` **精简掉 `EWOULDBLOCK`**（语义与 EAGAIN 相同）、部分固件 `socket` 缺 `SO_ERROR`，一律 `getattr` 兜底（`_EAGAIN/_EWOULDBLOCK/_EINPROGRESS/_SO_ERROR`，缺 SO_ERROR 时跳过查询交由后续 send/recv 暴露真实错误）；调用方 JSON 解析统一 `bytes(body).decode()` 后再 loads。真机回归（2026-09-16）：裸 import 崩 `'module' object has no attribute 'EWOULDBLOCK'` 已修复，`tests/test_stock.py` 移植性断言锁定（源码禁直引 errno.EWOULDBLOCK / socket.SO_ERROR 属性链）。
- **构建绑定**：`tools/build.py` FRAMEWORK_FILES 白名单登记；PC 仿真无需桩（CPython socket/select 原生可用，模式层由 stubs 注入假 http_nb 实现零真实网络，另见 tools/simulator/stubs.py 的 framebuf 桩——stock 离屏渲染依赖）。

### 2.12 网络电台服务（framework/radio.py + modes/radio.py，v2.4 新增；v2.5 流式；v2.6 零取数直连）

- **数据源**：闲沐盒子数据服务平台 `radio_relay`（**2026-09-18 起移除分段下载，唯一交付路径 = 流式端点**）：`GET /api/v1/stream/radio_relay?mode=mp3&station=<code>`——HTTP/1.1 chunked 长连接，audio/mpeg 连续透传，即时起播零转码；服务端首个听众到达才连上游（取数只声明与查询，TTL 30s，live/listeners 为缓存参考值），无人听 30 分钟回收；同一上游多听众共享广播（慢听众有界缓冲互不影响）；听众上限 10/台（总 30，超限 42901）；上游静默 >90s 结束听众流（重播即恢复）；上游真实地址只存服务端内存，目录/日志不回源。
- **盒子端 chunked 支持（v2.5 核心改造）**：平台文档标注「chunked 对现役固件不可用」指 urequests 不解 chunk 帧；本层 `_open_stream()` 用裸 socket + usssl 自实现（手工解析响应头 + `_make_chunked_read()` 手工解 chunk 帧——十六进制长度行 + 数据 + 尾 CRLF，撕裂边界安全；建连/TLS 10s、流读 30s 超时），read_fn 直供 `audio.play_mp3` 滑窗——不改固件接新契约（PC 实测 8s 真实流 69632B≈8146B/s，帧同步点 727）。错误路径为统一 JSON 信封（Content-Type: application/json 时解析业务码）：50301 停用/40401 无此台/40302 未订阅/40001 参数/42901 听众满。
- **接口（v2.6 零取数直连）**：`stream_url(code)` 由台代码直拼流端点完整 URL（格式稳定，收听路径零取数——直播即时起播无需先查状态）；`stations()` 台单为内置快照（10 台纯内存秒出；平台加新台需同步快照，滞后台选到时流端点 40401→「电台暂不可用」无害）；`play_stream(url, volume, on_progress, cancelled) -> (state, played_sec)` 直播流收听（state：ok=流结束（调用方 5s 后重连同一 url）/cancelled/limit=听众满/noent·stop=业务错/noauth=未订阅未绑定/badmp3/fail）；`media_url(path)` 平台相对路径拼接。
- **模式层**（`modes/radio.py`，RadioMode）：台单页（内置快照纯内存秒出、进模式即成页；每屏 6 行光标滚动窗口，A 下一台/B 收听/C 退出，光标定位 `settings.radio.last_station`）+ 播放页（阻塞接管直播循环：标题行与台单页同款样式——青色电台名+右侧直播点闪烁+分隔线，无通栏背景；状态行「正在接入」首秒回调切绿「正在收听」+ 右上已播 MM:SS、喇叭帧动画复用 `/icons/news_spk_N.raw`、y188 `LIVE` 信息行（直播无总长，无进度条）；A 换台/B 停止返回/C 退出，按键经 `play_mp3` 的 `is_cancelled` 回调逐帧打断）。直播循环：进台直连流；流结束 5s 短退避重连同一 url；连接/解码失败指数退避（15s×2→60s 翻倍上限 30 分钟）后重连同一 url（url 由台代码构造稳定）；听众满 60s；业务错等按键；无 mp3dec 固件进模式即提示页。
- **依赖与前提**：固件须含 `mp3dec` 模块（mp129-romfont-mp3dec 起，`audio.mp3_supported()` 探测）；设备须已在平台订阅 `radio_relay` 数据源（否则 40302 有文案）；取数限流 10 次/分钟/设备（直播收听仅在进台/换台/失败自愈时取数，安全）；真机待验证 usssl SNI（代码带缺参降级）与 TLS 流读吞吐（news 实测 124KB/s >> 64kbps 需求）。详见 `doc/网络电台模式功能文档.md`。

## 3. MODE_ID 解耦机制

### 3.1 设计原理

MODE_ID 是贯穿三层的唯一纽带，它是一个字符串，同时出现在三个位置：

```
app_config.py                     modes/registry.py                 modes/xxx.py
─────────────────────             ────────────────────             ─────────────────
MENU_ITEMS = [                     _MODULE_MAP = {                   class ClockMode(BaseMode):
  {"id": "clock", ...},  ────→      "clock": (...),    ────→           MODE_ID = "clock"
  {"id": "swipe", ...},              "swipe": (...),                     ...
]                                    ...                              }
```

### 3.2 为什么用字符串而非对象引用

| 方案 | 问题 |
|------|------|
| 对象引用（类直接注册） | 所有模式必须在 boot 时 import，无法懒加载，浪费内存 |
| 字符串 MODE_ID | 只需要存字符串，运行时才 `__import__`，退出后 del + `gc.collect()` |

### 3.3 独立性保证

- 删除一个功能：从 `app_config.py` 删一行 + `registry.py` 删一行。菜单不再显示，不影响任何其他功能。
- 添加一个功能：新建 `modes/xxx.py` + `app_config.py` 加一行 + `registry.py` 加一行 + `profiles/*.json` 加条目。
- Profile 驱动构建：`tools/build.py --profile X` 会按 `profiles/X.json` 自动生成 `app_config.py` 与 `modes/registry.py`。
- 无需 worry 索引号、无需 worry 顺序、无需 worry 其他模块。

## 4. 配置分层原则

### 4.1 四份配置的分工

| 文件 | 内容 | 修改时机 | 是否纳入版本控制 | 写入机制 |
|------|------|----------|------------------|----------|
| `devices/<device>.py` | 引脚、屏幕尺寸、硬件能力 | 换硬件时 | ✅ | build.py 复制到 build/ |
| `src/config.py` | `DEVICE_MODULE` 字符串 + 从设备档案加载的常量 | 自动生成 | ✅ | build.py 重新生成 |
| `src/app_config.py` | `MENU_ITEMS` 列表 | 功能编排时 | ✅ | build.py 按 profile 生成 |
| `src/settings.json` | WiFi / API Key / 亮度 / HTTP 端口 / 滑动参数（时区固定北京时间，不落配置） | 换网络/服务时 | ❌（含敏感信息） | 设备首次启动自动生成默认值；HTTP/设置菜单更新 |

> `secrets.py` 与 `swipe_settings.json` 已统一合并到 `settings.json`，所有读写均通过 `framework/settings.py` 进行。

### 4.2 配置加载链

```
boot.py
  ├─ from config import *            ← 硬件配置（DEVICE_MODULE → devices/<X>.py）
  ├─ from framework.settings import load_settings  ← settings.json（首次启动落盘）
  ├─ _apply_brightness(...)          ← 应用亮度档位 PWM duty
  ├─ from boot_animations.X import play  ← 开机动画
  ├─ from menus.X import run_menu    ← 菜单
  └─ from modes.registry import dispatch  ← 模式调度

menus/list.py    使用 MENU_ITEMS（来自 app_config.py）渲染菜单
framework/wifi.py 使用 settings.json.wifi 连接 WiFi（连接即关省电 `pm=0xA11140`，v1.6.1：避免 modem sleep 延迟尖峰影响流播/轮询；2026-09-19 修正：`config(pm=...)` 必须在 `active(True)` **之后**调用——esp_wifi 未初始化时 `esp_wifi_set_pm` 被驱动以 NOT INIT 拒绝，旧实现放在创建 WLAN 对象处被静默吞掉等于从未生效，现统一由 `_pm_off()` 在三处激活点（connect_wifi / reconnect_wifi / WiFiConnector.start）激活后设置）。`connect_wifi()` / `WiFiConnector.start()` **不信任 `isconnected()`**：软复位/重启后 WLAN 驱动层关联保留、但 LwIP 的 DHCP/DNS 配置已丢（表现为 NTP/HTTP 全部 DNS 失败 -202、开机时间停在旧值），两者均先 disconnect 并等待去关联完成（`_disconnect_for_reconnect`，最多 1.5s）再重连，让 DHCP 完整重跑（冷启动不受影响；直接 disconnect+connect 会被驱动拒绝 `Wifi Invalid Mode` 或静默忽略）。同理 SoftAP 侧：`provision.py` 启动热点必须**先 `active(True)` 后 `config(essid/authmode)`**（新设备 STA 从未激活时先 config 会 NOT INIT → "AP START FAIL"，见 WiFi配网功能文档第二节）
modes/ai_balance.py 使用 settings.json.api_keys 访问 AI 服务
modes/swipe.py    使用 settings.json.swipe 读取滑动参数
modes/settings.py 通过 framework/settings.update() 写回 settings.json
```

## 8. Profile 驱动构建流程

```bash
python tools/build.py --profile full --device esp32s3_n8r8
```

### 9.1 配网服务接口（framework/provision.py，v1.8.7）

与上表 STA 局域网配置服务**相互独立**：仅配网期间在 AP 热点网段（默认 192.168.4.1）可用，收摊即关。触发方式：① 开机 `main.py → boot_provision_check()`——WiFi 未连接自动进入设备端配网页（C 键跳过进离线菜单）；② 本机设置「WiFi配网」项。设备端子页按键：A=二维码/帮助页切换，B=重试已存凭据，C=退出。

| 方法 | 路径 | 行为 |
|------|------|------|
| GET | `/` | 配网页 HTML（深色科技风纯静态页：扫描列表点选 / 手输 SSID / 密码提交 / 状态轮询） |
| GET | `/api/provision/scan` | 周围热点列表 `{ok, aps:[{ssid,rssi,secure}]}`（RSSI 降序去重上限 15；试连进行中拒绝，防扫描打断连接） |
| POST | `/api/provision/save` | body `{ssid,password}`：凭据插首+同名去重+上限 5 写 `settings.json → wifi` 后非阻塞试连，返回 `{ok, state:"connecting", ssid}` |
| GET | `/api/provision/status` | `{ok, state, ssid, ip}`（idle/connecting/success/failed，附带推进一步状态机） |
| GET | 其余路径 | 302 → `http://<AP IP>/`（兼容 `/generate_204`、`/hotspot-detect.html` 等系统探测路径） |

配套机制：UDP 53 端口 DNS 劫持——所有查询应答 A 记录指向 AP IP（TTL 10s），手机连上热点后系统 Captive Portal 探测被劫持、自动弹出配网页（扫码进 `http://<AP IP>/` 为兜底入口）。连接成功后设备屏显示 IP 约 2.5s 自动退出并关闭热点/DNS/HTTP。完整说明见 [WiFi配网功能文档](WiFi配网功能文档.md)。

> **扫码入口（framework/qrcode.py，2026-09-06 起）**：本机设置「HTTP服务」项点击后进入全屏二维码子页——`framework/qrcode.py` 纯 MicroPython 编码 `http://IP[:端口]/`（byte 模式 V1~V3、ECC M、固定 mask 0，矩阵四边自带 2 模块空白），设置页 scale=5 逐模块绘制白底黑码，页内 B 键开关服务、A/C 返回列表；子页阻塞全局 tick，HTTP 请求由子页循环内 `poll_http_server()` 接管。编码正确性经 `tools/_check_qrcode.py`（OpenCV 解码还原 + 参考库矩阵比对）双重校验。

> **内存优化（http_server_state.py）**：`http_server.py` 体积较大（socket+json），boot.py 会在每次模式退出后将其从 `sys.modules` 移除释放内存；服务器 socket 引用单独保存在 `http_server_state.py` 中不被回收，避免模块卸载重载后重新 bind 报 `EADDRINUSE`。`modes/net_clock.py` 等通过该模块惰性探测服务是否开启，平时零内存开销。

## 10. 字体系统（v1.29-romfont 起）

### 10.1 三层命名（防混淆）

| 名字 | 是什么 | 位置 |
|---|---|---|
| `font` | Python 字体模块目录包（namespace package，部署到设备 /font/） | `src/font/`，只含 Python 模块 |
| `hanzi_24` | font 包内的全量汉字模块（标准字体接口） | `src/font/hanzi_24.py` |
| `romfont` | C 模块：只暴露固件 .rodata 中字体 .bin 的 memoryview | `firmware/romfont/`，编译进固件 |
| `hanzi_24_full.bin` | 字体数据资产（XMF1 格式），不进 src/font、不部署设备 | `firmware/romfont/` |

### 10.2 调用方式

```python
# 模式/框架代码（与旧 hz_24x24 同构，仅模块名变化，局部别名保持 hanzi24）：
from font import hanzi_24 as hanzi24
d.write(hanzi24, "开奖号码", x, y, fg, bg)   # st7789 write() C 端直接消费
hanzi24.MAP.index(ch); hanzi24._WIDTHS[...]   # 宽度查询照旧
hanzi24.HEIGHT                                # = 25，布局常量不变

# hanzi_24.py 包装层内部（应用代码不接触）：
import romfont
_b = romfont.data()   # memoryview 直指固件 .rodata，编译期地址绑定、零拷贝、零堆
```

### 10.3 数据与管线

- **渲染源**：`src/font/AlimamaFangYuanTiVF-Thin.ttf`（阿里妈妈方圆体，可变字体默认 Thin 实例），freetype-py `FT_LOAD_TARGET_MONO` 栅格化，与旧 hz_24x24 字模像素级同源。
- **字符集**：用户指定 ASCII（`0123456789a-z A-Z#$%&()*+,-./:;<=>?@[\]^_{|}~`）+ 空格（缺空格会导致 write() 不推进 x、混排跑版）+ GB2312 全区码点 ∩ TTF 覆盖。共 **6978 字形**（6763 汉字全覆盖 + 124 全角标点/符号 + 91 ASCII）。
- **基线冻结**：HEIGHT=25、基线 5、OFFSET_WIDTH=3（大端"位"偏移）为常量，随字符集扩大也不得重算，否则全部字模纵向漂移。
- **再生成**：`python tools/gen_full_font.py`——内置旧 370 字模逐位回归断言（369 渲染一致 + `…` 移植旧版位图，FreeType 版别差异自动兜底），输出 `firmware/romfont/hanzi_24_full.bin`（568772 B）与覆盖报告。
- **固件嵌入**：`.incbin` 进 .rodata（编译期地址绑定）；app 分区 1.94MB→3.5MB；构建细节见 `doc/固件构建指南.md` 4.4。

### 10.4 位图字体导出约定与完整性校验（2026-09-06 起）

- **导出约定**：`text()` 定宽位图字体（vga1_* 等）必须导出 `WIDTH/HEIGHT/FIRST/LAST/FONT`，其中 `FONT = memoryview(_FONT)` 是驱动取数的硬约定——缺该行即真机 `text()` 抛 `KeyError: FONT`（v1.8 曾因 `vga1_8x16.py` 文件截断缺行导致背单词真机崩溃，stock/swipe/ui_template 同受波及，2026-09-06 修复）；`write()` 变宽字库必须导出 `MAP/WIDTHS/OFFSETS/BITMAPS`；Hershey 矢量字体（italict）为 `_font/_index` 结构，经 `tft.draw()` 基线坐标消费。
- **静态校验**：`tests/test_fonts.py` 扫描 src/font 全部 .py 字体按上述约定校验（tools/test.py 的 Font Integrity 套件）；仿真器 stubs 优先加载 src 真实字体文件，不再用派生字体遮蔽设备字体缺陷；SimDisplay 已实现与设备驱动对齐的 Hershey `draw()` 桩。

### 10.5 已知边界

- GB2312 符号区 558 个装饰字符（假名/西里尔/注音/罗马数字/制表符/全角字母数字）方圆体无字形，不收录——驱动对其静默跳过，与历史行为一致。
- GB2312 之外的生僻字（如"喆""堃"）同样空白跳过；如需兜底可在 C 端加 fallback 字形（后续可选）。
- 历史小字库 `hanzi1k/hanzi100/duanyu24/stockchars/digitalnumbers/sy_32x32/hanzi32` 仍走文件系统（morse/stock 等仍在用），换用与退役另行批次；vocab 已于 2026-09-06 迁至 hanzi_24 + italict。

## 11. MP3 软解码（v1.29-romfont-mp3dec 固件起，2026-09-17）

### 11.1 组成与分工

| 名字 | 是什么 | 位置 |
|---|---|---|
| `mp3dec` | C 模块：封装 minimp3（CC0 公有领域）暴露逐帧解码 | `firmware/mp3dec/`，编译进固件 |
| `audio.play_mp3()` | 框架播放层：滑窗供数 + I2S 写入 + 取消/进度 | `src/framework/audio.py` |
| `mp3dec`（仿真桩） | 合成帧容器镜像 C 模块契约，供 PC 仿真/单测 | `tools/simulator/stubs.py` |

固件 C 模块链：`USER_C_MODULES=/work/romfont/micropython.cmake` 单入口，链序 romfont → st7789 →（lvgl，仅储备线）→ mp3dec。版本锁定与产物记录见 `doc/固件版本履历.md`。

### 11.2 解码契约（Python 滑窗必须遵守）

`mp3dec.Decoder().feed(buf, out, vol_shift=8) -> (consumed, pcm_len, samples, rate, channels)`：

- **逐帧解码**：每次调用解一帧（MPEG1 层 III 最多 1152 采样/帧，`MAX_SAMPLES_PER_FRAME` 常量可查）；
- **滑窗供数**：`consumed=0 且 samples=0` 表示数据不足，调用方补数据后重试；`consumed` 把帧前垃圾字节/ID3 标签一并计入（流式重同步），调用方按其滑动窗口；
- **输出统一立体声 16bit**：单声道帧复制 L=R、立体声帧透传，与 I2S STEREO 模式（2.9 节绕过 MONO bug 的约定）直接对接；`out` 为调用方预分配 bytearray（≥4608B，C 侧零分配）；
- **软件音量在 C 侧**：`vol_shift` 0-8 右移（对齐 `audio._vol_shift` 映射），44.1kHz 下 Python 不再做逐样本循环；
- `rate/channels` 仅 `samples>0` 时有效；`dec.reset()` 换曲清状态；单实例堆占用约 12KB（GC 回收，无需 close）。

### 11.3 播放循环要点（audio.play_mp3）

- 缓冲策略：未消费量低于 `_MP3_KEEP`(8KB) 才补数、目标 `_MP3_FEED`(16KB)；补数阈值兼作坏数据线——达线仍解不出任何帧即返回 `"bad mp3"`（防死循环）；
- 进度按累计采样数折算整秒回调（≤1 次/秒），与 play_wav 的块进度语义一致；
- I2S 首帧成功后才知道采样率，此时才 `_ensure_i2s(rate)`；结束 `deinit()` 在 finally；
- 老固件无 mp3dec：`play_mp3` 返回 `(False, "no decoder")`，`mp3_supported()` 可探测，调用方据此降级 WAV 路径（v2.3 起新闻播报已接入：`_resolve_audio_url` 解析阶段即按能力选择格式，见 2.9 节）。
