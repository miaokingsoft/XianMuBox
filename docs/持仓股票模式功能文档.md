## 一、功能概述

金融终端风格的实时持仓看板：纯黑底 + 红色顶栏 + 白底按钮，**每只持仓股票三个场景**（B 键循环）。

1. **三场景**：场景1 简易行情（现价大字 + 涨跌幅徽章双焦点）→ 场景2 明细数据（12 项两列表）→ 场景3 预测K线（满宽网格/成交量带/AI 预测段）；
2. **双数据源**：持仓与预测 K 线走 mooview 接口（数据有效）；实时现价/涨跌/盘口明细走腾讯免费接口批量刷新，**交易时段每 10s 一次**（一次批量覆盖全部持仓 ≤20 只；非交易时段 10min）；
3. **降级链**：腾讯主域名失败→换备用域名重试一次→仍失败走 `urequests` 阻塞兜底（与 mooview 同款自愈，成功后转粘滞阻塞模式）→三层都失败才静默回退 mooview 持仓价（来源标记 TX/MV + 时间戳上屏，用户可辨数据新旧）；
4. **零闪烁渲染**：每场景整页绘入 240×240×2 字节离屏画布后单次 `blit_buffer` 上屏，10s 行情刷新与数据变化都是整页原子换帧；
5. **不冻结**：全部 HTTP 走 `framework/http_nb` 非阻塞状态机，等待数据期间进度条动画连续推进；按键反馈非阻塞（无 sleep 阻塞）；
6. **红涨蓝跌**：中国股市配色习惯（现价/涨跌幅：涨红跌蓝；持仓盈亏：盈红亏绿反向）；
7. **持仓只拉一次**：进入模式拉取一次持仓列表后不再周期刷新；读取失败停在网络中断页时按 B（按钮标签变「重试」）重新拉取。

## 二、页面结构与导航

```
进模式 → 拉持仓+行情 → 场景1 简易 --B--> 场景2 明细 --B--> 场景3 预测K线 --B--> 场景1...
                        ^---------------------------- B 循环 ------------------------------|
A短按: 三场景均=切换下一支持仓(循环, 300ms 滑动过场); 场景3 切股后按需拉取该股 K 线
C短按: 任意场景 → 退出模式
```

## 三、按键表（全模块一张表）

| 场景 | A | B | C |
|------|---|---|---|
| 场景1 简易 | 下一支持仓（循环+滑动过场） | 进入场景2 明细 | 退出模式（`flash_exit()`） |
| 场景2 明细 | 下一支持仓 | 进入场景3 预测K线（按需拉取） | 退出模式 |
| 场景3 预测K线 | 下一支持仓（重新按需拉取 K 线） | 回场景1 简易 | 退出模式 |
| 空态（加载中/暂无持仓/网络中断） | —（无持仓时空操作） | **重试**：重新拉取持仓列表（按钮标签由「明细/K线/简易」变「重试」） | 退出模式 |

- 底部按钮区与按键一一对应（B 键标签=按下后进入的场景）：场景1 `翻页 / 明细 / 退出`，场景2 `翻页 / K线 / 退出`，场景3 `翻页 / 简易 / 退出`；
- 无长按/双击手势（符合框架按键规范 2.4；v1.4 文件头"B 长按"注释已废弃）。

## 五、运行规则

| 规则 | 行为 |
|------|------|
| 持仓获取 | mooview `action=user`，**仅进入模式时拉取一次**（非阻塞，完成后原子换帧）；读取失败停网络中断页，按 B（「重试」）重新拉取；无周期刷新（v2.3 起取消原 60s 周期） |
| 实时行情刷新 | 腾讯批量接口，**交易时段（周一~五 9:15-15:05，RTC 判定）每 10s**；非交易时段降频 10min/次（收盘快照） |
| 降级链 | **腾讯行情三级**：主域名非阻塞 → 备用域名 `web.sqt.gtimg.cn` 非阻塞（`_quote_try_bak` 每刷新周期复位，主/备各得一次机会）→ `urequests` 阻塞兜底（`quote_legacy`；成功后置粘滞标志 `_quote_blocking`，后续周期直接走阻塞，省掉每周期一次 6s 非阻塞空等）；三层全失败才静默回退 mooview 持仓价（来源 `MV`，时间戳 `--:--`），并把原因写入 `_quote_err`（场景2 空态上屏）；**mooview 非阻塞读取解析失败（user/kxian）→ v1.4 同款 urequests 阻塞兜底一次**（`user_legacy`/`kxian_legacy` 请求；限次规则：user 每次进入模式限一次（`_legacy_tried`）、kxian 每 code 限一次（`_kline_legacy`），两者均随 `enter()` 复位；串口打印 fallback 日志），兜底也失败才显示网络中断（含具体原因：`truncated`/`timeout`/`dns:`/`HTTP xxx`/`BAD JSON` 上屏 + 串口 body 长度与尾部 80 字节） |
| 盈亏重算 | 有实时价时 `(现价−成本)×股数` 现算（比 mooview 原生盈亏更实时）；无实时价用 mooview 字段 |
| K 线拉取 | 进场景3 或场景3 切股时按需拉取；**成功结果**按 `code` 缓存 30 分钟（含 `forecast_start` 索引）；在途请求去重（`_kline_pending`）；**失败不落缓存**（写入的 `{"bars": None}` 在 `_ensure_kline` 中因 `bars` 为假视为未命中），故每次进场景3 都会重跑一轮「非阻塞 → 阻塞兜底」 |
| 自动翻页 | 120s 周期切下一支持仓（保持当前场景；滑动过场） |
| 数据解析 | K 线合并 `history` + `forecast`，`forecast_start = len(history)`；腾讯响应按 `~` 切分逐 ASCII 字段解码（GBK 名称字段不解析，名称取自 mooview）；**两侧代码一律经 `stock_quote.norm_code()` 归一为裸码**（剥 `sh/sz/bj` 前缀与 `.SH/.SZ` 后缀），保证 `_quotes` key 与持仓 `code` 相等 |
| 代码前缀 | `market_prefix`：6/5/9→`sh`、0/3/1/2→`sz`、4/8→`bj`；首位无法判定时原样传递（腾讯侧无效行被解析层跳过，静默不影响其他持仓）。输入先经 `norm_code` 归一，故 `600519.SH` 这类带后缀写法也能拼出正确 URL |

## 六、性能与资源

- **离屏渲染**：每场景整页绘入 `framebuf.FrameBuffer`（115KB，RGB565 小端存储 + 颜色值交换 = 大端缓冲），单次 `blit_buffer` 上屏（约 23ms）——数据刷新/场景切换零闪烁；300ms 滑动过场用三画布 `blit` 合成（`_cv` 当前 / `_cv_n` 新场景 / `_cv_w` 合成），全 C 级内存拷贝；
- **离屏文字**：vga 定宽与 stockchars 比例字体均有 Python 位图 blitter（`_fb_text`/`_fb_hanzi`），整页重渲约 30-70ms，仅发生在数据变化帧（10s 周期）；
- **非阻塞网络**：`framework/http_nb.Request` 状态机（DNS→连接→发送→接收，`uselect.poll` 单帧步进，单帧预算约 20ms）；HTTPS endpoint 自动回退阻塞模式（`get_json_blocking`）；响应体上限 96KB，超时 6-9s；加载动画期间 UI 帧率不降；行情链路另有原始字节版阻塞兜底 `get_text_blocking`（腾讯响应非 JSON，`get_json_blocking` 不适用），触发时单次阻塞约 0.3-1s，且仅在失败周期触发（成功后转粘滞阻塞模式）；
- **按键反馈**：按下直接绘屏黄底，250ms 后从画布条带（`y199` 整行连续内存）重blit 恢复，全程无 `sleep_ms` 阻塞；
- `exit()` 置空 `_stocks/_quotes/_klines` 与三块画布并 `gc.collect()`；
- 测试：`tests/test_stock.py`（数据层 14 项：前缀/URL/GBK解析/停牌/URL解析/Content-Length/chunked/截断/交易时段 + **代码归一 norm_code** + **sz/bj 前缀剥离** + **49 字段阈值** + `http_nb` 移植性常量约束 + JSON NaN/Infinity 清洗）+ `tools/_sim_stock.py`（三场景 40 项仿真断言，含**明细页内容断言**与**阻塞兜底自愈用例** + 拼图 `tools/shots/sim_stock.png`）。
