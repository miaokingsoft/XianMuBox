# 网络电台模式（RadioMode）功能文档

> 模块路径：`src/modes/radio.py`（`RadioMode`）；服务层 `src/framework/radio.py`
> 关联资源：`font/hanzi_24`（台名/状态文案）、`font/vga1_8x8`（页码/信息行/按键提示）、`/icons/news_spk_0~3.raw`（播放页喇叭帧动画，与新闻播报共用素材）、`/icons/radio.png`（菜单图标，48×48）
> 配置文件：`settings.json` → `radio` 节点（`volume` 音量 0-100 默认 80、`last_station` 上次收听电台代码）
> 构建绑定：`profiles/full.json → {"id": "radio", "module": "modes.radio", "class": "RadioMode"}`
> 最近更新：2026-09-19（v2.6：收听路径零取数——stream_url 由台代码直拼进台即连流，台单纯内置快照；v2.5：迁移平台纯实时流式契约；v2.4.x 历史：分段方案已废弃）

## 一、功能概述

收听闲沐盒子数据服务平台 `radio_relay` 电台转播（央广中国之声、广东音乐之声等），纯实时流式类直播收听。

1. **纯实时流式（v2.5）**：唯一交付路径 = 流式端点 `GET /api/v1/stream/radio_relay?mode=mp3&station=<code>`（HTTP/1.1 chunked 长连接，audio/mpeg 连续透传，即时起播零转码）；服务端首个听众到达才连上游，无人听 30 分钟回收；同一上游多听众共享广播；上游静默 >90s 结束听众流（重播即恢复）
2. **固件自实现 chunked**：平台文档标注「chunked 对现役固件不可用」指 urequests 不解 chunk 帧；本固件用裸 socket + usssl 手工解析响应头与 chunk-size 行（`_make_chunked_read`），供 `audio.play_mp3` 逐块供数——不改固件即接新契约（PC 实测：8s 真实流收 69632B ≈ 8146B/s，727 个 MP3 帧同步点）
3. **直连直播零取数（v2.6）**：stream_url 格式稳定，由台代码直接构造（`stream_url(code)`），进台即连流；台单为内置快照（10 台纯内存秒出，与平台目录一致；平台加新台快照滞后时新台显「电台暂不可用」无害）；上游真实地址只存服务端内存，设备永远只见 stream_url
4. **错误分级退避**：断流（流结束）复用 stream_url 5s 短退避重连（不重新取数）；连接/解码失败指数退避（15s×2 → 60s 起翻倍上限 30 分钟）并重新取数自愈；听众已满（42901，上限 10/台/总 30）60s 重试；业务错（未订阅/无此台/停用）不自动重试
5. **固件依赖**：需含 `mp3dec` 模块的固件（mp129-romfont-mp3dec 起），无解码器进入即提示「请更新固件」

## 二、页面结构与导航

```
台单页(默认, 内置快照秒出) --B--> 播放页(阻塞接管)
播放页 --B--> 返回台单页
播放页 --A--> 换下一台(循环, 留在播放页)
C短按: 台单页/播放页 → 退出模式
固件提示页(无 mp3dec 时, 任意键 → 退出模式)
```

## 五、后台服务 / 业务规则

模式为按需收听型，无后台定时器（BaseMode.run 每帧的全局闹钟/新闻/云端检查在播放页阻塞接管期间暂停，与新闻播报页惯例一致）。直播循环状态机（`_listen`）规则：

| 规则 | 行为 |
|------|------|
| 直播循环（v2.6 零取数） | 进台由台代码直拼 stream_url → `play_stream` 建流式连接边下边播 → 流结束（上游静默 >90s 服务端断流，直播无「播完」概念）→ 5s 短退避重连同一 url |
| 连接/解码失败 | 「信号中断」/「解码异常」走指数退避（`_net_wait_sec`：15s×2 → 60/120/240... 上限 30 分钟）后重连同一 url（url 由台代码构造，稳定，无需刷新） |
| 听众已满 | 流端点错误信封 42901（上限 10/台、总 30）→「听众已满」60s 后重连 |
| 业务错 | 无此台（40401）→「电台暂不可用」、服务停用（50301）→「电台服务未开放」、未订阅/未绑定（40302/40101/40102）→「未订阅电台源」：均不自动重试等按键 |
| 换台 | 播放页 A：打断当前流 → 光标索引 +1 循环 → 直连新台 url |
| 记忆 | 每次开始收听把电台代码写入 `settings.radio.last_station`（台单页光标自动定位） |
| 服务端语义 | 取数只做声明与查询（TTL 30s），不触发建连；首个听众到达流端点才连上游；慢听众有界缓冲，播放不动服务端即断开（不影响他人）。收听路径不取数（v2.6 用户决策：直播无需先查状态） |

## 六、性能与资源

- 服务层 `framework/radio.py` 惰性 import（usocket/ussl/ujson/settings/cloud 均函数内导入），台单纯内存（取数时吸收，零网络）
- **chunked 流式客户端**：裸 socket + ssl/ussl 双名兼容（带 `server_hostname` SNI，旧固件缺参降级），建连与流读统一 30s 超时——**v1.20 SSLSocket 无 `settimeout` 方法（仅 read/write/close），超时必须在 wrap 前设在原生 socket 上**（wrap 后读阻塞继承底层，新固件 wrap 后 try 覆盖）；chunk 帧手工解（十六进制长度行 + 数据 + 尾 CRLF，撕裂边界安全）；任何读超时/断流关流返回 EOF——`play_mp3` 正常收尾，上层断流语义接管
- `audio.play_mp3` 滑窗供数（16KB 补数窗），无整流进 RAM；播放页动态 UI 由 `on_progress` 每秒驱动（喇叭帧变化才 blit 约 3-5ms/帧）
- 模式退出 `exit()` 清空台单/字体/帧缓存并 `gc.collect()`；喇叭帧 raw 首次使用读入常驻缓存（4 帧共 80KB），缺失纯黑降级

## 七、数据依赖

| 数据 | 来源 | 缺失表现 |
|------|------|----------|
| 电台目录 | 固件内置快照（10 台，纯内存，2026-09-19 与平台目录一致；平台加新台需同步快照） | 无（快照即台单） |
| 直播流 | `GET <endpoint>/api/v1/stream/radio_relay?mode=mp3&station=<code>`（chunked 长连接，audio/mpeg；校验顺序 stream_enabled→路由→鉴权→参数→上限，错误路径为统一 JSON 信封） | 断流复用 url 重连；连接失败指数退避重取数 |
| 音量 | `settings.json` → `radio.volume`（0-100） | 异常回退 80 |
| 上次电台 | `settings.json` → `radio.last_station` | 光标回第 1 台 |
| 喇叭帧素材 | `/icons/news_spk_0~3.raw`（build 由 80×80 PNG 转 RGB565，新闻共用） | 动画区纯黑（不影响播放） |
| 合规标注 | 取数 `payload.source_name`（转播来源+仅供个人收听，串口日志可查） | 无（平台侧义务字段） |

## 八、状态与已知问题

- **v2.5 契约迁移**（2026-09-19）：平台 2026-09-18 起移除分段下载（旧 latest.mp3 段端点陆续 404——此前 6 台 404 即迁移结果），唯一交付路径 = 流式端点；v2.4 分段方案全部废弃
- **PC 端到端实测**（同日）：流端点 200/chunked/audio-mpeg 无鉴权可访问；真实解帧代码 8s 收 69632B（8146B/s ≈ 64kbps+开销），MP3 帧同步点 727
- **真机坑两枚（09-19 已修）**：① mp129 固件 TLS 模块名为 `ssl`（v1.20 ESP32 weak-links 命名）无 `ussl` 别名——双名兼容；② `SSLSocket` 无 `settimeout`（wrap 后调用崩）——超时改 wrap 前设原生 socket。**真机待验证项**：SNI 实际生效性（server_hostname 路径）；直播断流重连的真实节奏；长时收听内存稳定
- **订阅前提**：设备需已在平台订阅 `radio_relay` 数据源（流端点 stream_require_auth=true 时校验），否则 40302（页面有文案）
- **仿真器限制**：`tools/simulator` urequests/socket 桩禁网，仿真永远走假服务层；流式客户端已由「假 socket 撕裂分片单测 + PC 真端点实测」双覆盖
- 冷启动：首个听众到达才建上游连接，头几秒缓冲空属正常直播缓冲；无人听 30 分钟服务端回收
- 待真机回归：进台起播、断流重连、换台、长时收听内存稳定
