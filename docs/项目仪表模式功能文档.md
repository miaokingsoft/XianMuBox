# 项目仪表模式（Dashboard）功能文档

> 模块路径：`src/modes/dashboard.py`（`DashboardMode`）
> 关联资源：`font/hz_24x24.mpy`（标题/字段行）、`icons/dashboard.png`（顶栏图标）、`icons/loading_120.png`（进模式过渡画面，由 registry 统一显示）
> 配置文件：`settings.json → project.own_sites`（动态站点列表，Web 配置页可编辑）
> 构建绑定：`profiles/full.json → {"id": "dashboard", "module": "modes.dashboard", "class": "DashboardMode"}`
> 最近更新：2026-09-01（按统一模板重写；对照动态版源码更正字段标签/URL 拼接/刷新行为）
> 第三方接入规范：`doc/项目仪表API接入规范.md`（站点方按此提供 API）

## 一、功能概述

多站点动态数据看板：从 `settings.json → project.own_sites` 读取站点列表，通过各站点 HTTP API 拉取实时数据，每站点一张卡片分页展示。

1. **动态字段渲染**：卡片自动列出该站点 API 返回的所有字段（字段名 → 字段值），无需为站点硬编码 UI；
2. **分步加载**：每轮主循环至多请求一个站点——进模式先显示 loading 过渡画面，首个站点数据返回即切卡片视图，其余站点后台逐个加载；
3. **60s 周期刷新 + 自动轮播**：刷新完一轮自动切到下一张卡片；
4. **友好降级**：单站点失败标红"数据获取失败"，不影响其他卡片；无配置时空态提示；
5. **键名即显示名**：API 返回的 JSON 键名直接作为显示标签（键名中的 `_` 替换为空格），站点方直接返回中文键名即可获得中文界面。

## 二、页面结构与导航

单页多卡片视图：

```
进模式 → loading_120.png(registry 过渡) --首站点数据到达--> 卡片视图(逐站后台加载)
空配置 → 空态页(仅等 C 退出)
C短按: 任何状态 → 退出模式
```

## 三、按键表（全模块一张表）

| 页面 | A | B | C |
|------|---|---|---|
| 卡片视图 | 下一张站点卡片（循环，900Hz/15ms） | 立即刷新全部站点数据（800Hz/15ms） | 退出模式（`flash_exit()`） |
| 空态页 | 不响应 | 不响应 | 退出模式 |

- 只读展示型模式，无长按/双击；符合按键统一规范（A=翻页、B=主操作、C=退出）。

## 四、各页布局（240×240）

| 区域 | y 范围/坐标 | 内容 |
|------|------------|------|
| 顶栏 | 0~40 | 蓝色背景（`CLR_CYAN` 系），左：站点名（hanzi24）；右：dashboard.png 图标 |
| 字段列表区 | y50 起，行高 30px | 每行 `字段名：值`——前 5 行 hanzi24 大字（字段名左对齐 x=10，值右对齐），更多字段自动收缩 |
| 日期行 | y205 | 居中灰色日期 |
| 分页指示器 | y225 | 小方块 6×6、间距 4，数量=站点数；当前卡绿色（`CLR_GREEN`），其余暗色 |

### 空态页

顶栏照常绘制（标题"项目仪表"，保持视觉一致），居中"未配置站点 / 请在设置中添加"，底部小字提示。

## 五、运行规则

### 5.1 分步加载与刷新

| 阶段 | 行为 |
|------|------|
| 进模式 | `_load_step` 状态机启动，每轮 loop 请求一个站点；首个站点数据到达立即绘制卡片视图 |
| 60s 周期刷新 | 重置加载状态逐站点刷新（复用同一状态机，不阻塞 UI），完成后**自动轮播到下一张卡** |
| 手动刷新 | B 键立即刷新全部站点后重绘当前卡 |

### 5.2 数据解析

支持两种 JSON 响应结构：

- **嵌套**：`{"success": true, "data": {...}}` → 取 `data` 子对象；
- **平铺**：字段直接在顶层 → 剔除 `success` / `error_code` / `message` / `__error__` 元字段后全部采用。

字段显示顺序即 API 返回顺序，键名 `_` → 空格后直接作为标签（站点方返回中文键名即得中文界面）。

## 六、性能与资源

- HTTP 用 `urequests`，`finally` 中关闭 response 防套接字泄漏（与 stock.py 同一套写法）；
- 每拉取一个站点 `gc.collect()`，长时间运行内存平稳；
- 分步请求保证任意时刻至多一个站点在传输，UI 按键始终有响应；
- 仅 loading 过渡 PNG + 顶栏图标两个图片资源，无常驻大对象。

## 七、数据依赖

| 数据 | 来源 | 缺失表现 |
|------|------|----------|
| 站点列表 | `settings.json → project.own_sites`（`name=="stock"` 为保留字被过滤，由股票模式独立处理；无 `api` 的条目跳过） | 空态页 |
| 站点数据 | `GET <api>?api_key=<key>`（key 为空则不带参数；URL 已含 `?` 时用 `&` 拼接） | 卡片红色"数据获取失败" |
| 字段值 | 站点 API JSON（见 5.2 两种结构） | "暂无数据"（灰） |

**站点配置字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 站点名（顶栏标题），`stock` 保留 |
| `api` | ✅ | 完整 API 地址（http/https） |
| `key` | ❌ | API Key，拼为 `api_key` 参数 |

> 新增站点：Web 配置页或直接编辑 `settings.json → project.own_sites` 追加条目，API 返回格式按 `doc/项目仪表API接入规范.md`。
