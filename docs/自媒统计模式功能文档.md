# 自媒统计模式（Self Media）功能文档

> 模块路径：`src/modes/self_media.py`（`SelfMediaMode`）
> 关联资源：`icons/self_media.png`（轮播占位图）、`icons/{douyin,kuaishou,xiaohongshu,bilibili}.png`（平台 80×80 大图标，构建时同步生成 RGB565 `.raw`）、`icons/{fans,works,likes,views}.png`（详情页数据项图标）、`icons/contact.png`（顶栏联系人）、`font/hz_24x24.mpy`（中文）
> 配置文件：`settings.json → project.self_media`（账号列表，Web 配置页可编辑）
> 数据源：按每平台 `url` 拉取 JSON `{fans, works, likes, views}`；缺失/失败回退内置 `_MOCK_DATA`
> 构建绑定：`profiles/full.json → {"id": "self_media", "module": "modes.self_media", "class": "SelfMediaMode"}`
> 最近更新：2026-09-01（按统一模板重写；对照源码更正数据加载策略为后台分步预取）

---

## 一、功能概述

多平台轮播式自媒体数据看板：抖音 / 快手 / 小红书 / B 站账号数据统一收纳，"平台轮播 → 详情页"两层结构。

1. **配置化平台**：`project.self_media` 数组动态决定平台与顺序，category 白名单过滤，名称可覆盖；
2. **永远可演示**：空配置自动填充 4 个内置演示平台；url 缺失或拉取失败回退 `_MOCK_DATA`，UI 不出现空白；
3. **图标三级降级**：平台大图标优先 `.raw` 裸缓冲 blit（无 PNG 解码）→ `icons/{category}.png` → 程序绘制；
4. **后台分步预取**：每轮 loop 至多拉取一个平台（dashboard 同款状态机），UI 不阻塞；
5. **滑动动画**：平台切换 10 步 × 12ms 平移过渡（RGB565 raw blit 逐帧内存拷贝，裁剪 blit 支持越界坐标）。

## 二、页面结构与导航

```
第1页 轮播入口 --B--> 第2页 平台详情(粉丝/作品/获赞/播放)
     ^----A----（返回轮播）----//
A短按(第1页): 下一平台(右滑动画)
B短按(第2页): 清空当前平台数据并重新拉取刷新
C短按: 任意页 → 退出模式
```

## 三、按键表（全模块一张表）

| 页面 | A | B | C |
|------|---|---|---|
| 第1页 轮播入口 | 下一平台（800Hz/15ms + 滑动动画） | 进入当前平台详情（1200Hz/30ms + 闪白确认） | 退出模式（`flash_exit()`） |
| 第2页 平台详情 | 返回轮播首页（900Hz/15ms） | 手动刷新当前平台数据（清空 fields 后重拉重绘） | 退出模式 |

- 符合按键统一规范（A=翻页、B=主操作、C=退出），无长按。

## 四、各页布局（240×240）

### 4.1 第 1 页：轮播入口

| 区域 | 内容 |
|------|------|
| 顶栏 0~50 | 平台名 + 联系人图标（`contact.png`，缺失降级程序绘制双人形） |
| 中部 | 平台大图标 80×80 居中（.raw → PNG → 程序绘制三级降级）+ 左右 chevron（垂直居中 y=117） |
| 平台名行 | 图标下方中文平台名（最长 4 汉字，超长截断） |
| 分页点 y≈226 | 5px 方块一行，当前平台青色 |

### 4.2 第 2 页：平台详情

| 区域 | 内容 |
|------|------|
| 顶栏 0~50 | 绿色顶栏：平台名 + 联系人图标 |
| 平台大图标 | 平台专属 80×80 图标（chevron 居中 y=112） |
| 2×2 数据网格 | 粉丝（fans，双人轮廓）/ 作品（works）/ 获赞（likes，心形）/ 播放（views）——每格：20×20 图标 + 中文标签 + 大号数值 |

- 数值绘制：`vga1_16x32` 缺失时用 `hz_24x24` 内置数字字形 + 像素描边模拟 24 高度字体；数据项小图标缺失降级灰描边方框。

## 五、运行规则

| 规则 | 行为 |
|------|------|
| 平台加载 | category 白名单（douyin/kuaishou/xiaohongshu/bilibili）外静默丢弃；name 空→默认名；**空配置自动填充 4 个内置演示平台** |
| 分步预取 | `_load_step` 状态机每轮 loop 拉一个平台；无 url 的平台直接填 Mock 兜底 |
| 详情刷新 | B 短按清空 `fields` 后重绘，`_draw_detail` 内部重新拉取 |
| 数据缓存 | 拉取结果写入 `platform["fields"]`，会话内常驻，退出模式清空 |
| 字段校验 | 四字段强制 `int()` 转换，非法/缺失按 0 |
| 超时 | HTTP 8s；失败打印日志并回落 Mock |

**单位格式化**（`fmt_num`）：`<1w` 原值；`1w ≤ n < 1ww` → `8w` 风格（去 `.0`）；`≥1ww` → `1.2ww` 风格。

## 六、性能与资源

- **raw blit 动画**：平台图标构建期生成 RGB565 `.raw`，切换动画 10 步 × 12ms 每帧仅 `blit_buffer` 内存拷贝；裁剪 blit 使用暂存缓冲避免逐帧分配；
- **raw 缓存**：`_raw_cache` 按 category 缓存（含"不存在"标记，避免重复探测文件）；
- **分步拉取**：每轮 loop 至多一个 HTTP 请求 + `gc.collect()`，切页/动画不被阻塞；
- `exit()` 置空 platforms 并 `gc.collect()`。

## 七、数据依赖

| 数据 | 来源 | 缺失表现 |
|------|------|----------|
| 平台列表 | `settings.json → project.self_media`：`[{category, name, url}, ...]`（category 必须 ∈ 白名单；name 截断 32 字符；url 截断 512 字符） | 空配置 → 内置 4 平台演示数据 |
| 平台数据 | `GET url` → `{fans, works, likes, views}`（200 且为 dict 才采用） | `_MOCK_DATA` 兜底（douyin/bilibili 8881 粉、kuaishou 1234 粉、xiaohongshu 5678 粉等演示值） |
| 平台图标 | `/icons/{category}.raw` → `/icons/{category}.png` → 程序绘制 | 逐级降级，不崩 |

**平台 category → 默认名**：douyin=我的抖音、kuaishou=快手、xiaohongshu=小红书、bilibili=B站UP主（`name` 字段可覆盖）。

## 八、状态与已知问题
